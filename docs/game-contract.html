Game API reference

This is the human page for the Game and Helper contract. Each method has a signature, parameters, return value, a longer explanation, and at least one named example. Agents should still start from docs/agent/GAME_CONTRACT.md. The Go types in internal/games/game.go win if any of this disagrees with the code.

The pattern follows MDN method pages and Go-style godoc. Lead with what the call does. Then show the exact signature. Then parameters, return value, when it runs, and copyable Go from the Testing package where that package already does the job.

Overview

Lobby owns roster, join, wait list, audience, seats, identity, operator knobs, and the start gate. A game reads those facts through games.Helper. It never writes them.

A game owns run logic, per-player run state keyed by Lobby player id, optional extra pages, the full /board document after Start, and the inner phone body on / after Start.

Host drives Load, Start, Stop, and Shutdown. Load constructs the selected package in-process. There is no folder scan and no child process.

Package games cannot import a child game. The child imports games for Helper and Register. Host blank-imports each child so Catalog fills in.

Load a game

Compile-time, in this order:

  1. Add internal/games/<name>. Do not name the package testing. Product Testing uses package testinggame.
  2. Implement games.Game.
  3. Call games.Register from init.
  4. Blank-import the package from internal/host/handler.go.

Runtime Load is POST /settings/load. Admin session. Restore prompt is not pending. No round is started. Catalog contains the id. If MaxPlayers is greater than 0, seated count must be at or under that max. Host creates <dataDir>/games/<ID>, then calls Load.

Start still needs at least one seated player. If MinPlayers is greater than 0, seated count must also meet that floor.

gamesinit

Register

Adds a compile-time game factory to the in-process catalog.

Syntax

func Register(f Factory)

Parameters

f
Factory with a non-empty ID and a non-nil New. Empty ID or nil New is dropped with no error and no log line.

Return value

None.

Description

Call this from init in the game package. Host never calls Register itself. Duplicate IDs are not rejected here. The last factory host indexes by ID wins in the runtime map. Keep IDs unique.

Examples

Register Testing
package testinggame

import "github.com/KroniK907/grabbag/internal/games"

func init() {
    games.Register(games.Factory{
        ID:  "testing",
        New: func() games.Game { return New() },
    })
}
Blank-import so Catalog is not empty

Without this line in internal/host/handler.go, Load returns conflict for that id.

import (
    _ "github.com/KroniK907/grabbag/internal/games/testing"
)

MinPlayers

Returns the extra seated-count floor required before Start.

Syntax

MinPlayers() int

Parameters

None.

Return value

0 means the game does not declare a floor. Host still requires at least one seated player. A positive value refuses Start when seated count is below it.

Description

This is not the Lobby seat cap. Lobby already has its own cap. Use MinPlayers when the rules need a table of a certain size, such as two teams.

Examples

GameLoad gate

MaxPlayers

Returns the extra seated-count ceiling applied at Load and stored on Lobby.

Syntax

MaxPlayers() int

Parameters

None.

Return value

0 means the game does not declare a ceiling. The Lobby seat cap still applies. A positive value refuses Load when seated count is already above it, then host calls SetGamePlayerMax with that value.

Description

Load checks this before Load(helper). Start does not re-check MaxPlayers. If you need a hard table size, declare it here so Lobby stops filling extra seats.

Examples

No extra ceiling

Gamelifecycle

Load

Stores the host Helper and prepares settings after the operator picks this game.

Syntax

Load(h Helper) error

Parameters

h
Host-owned Helper. Keep this pointer. You will need it on later requests. Host may pass the same helper again on Start.

Return value

nil on success. Any other error rolls the previous loaded id back. The operator sees a generic load failure.

Description

Host has already created <dataDir>/games/<ID>. KV from earlier sessions is already there. Read knobs in Load or on each settings render. Do not start the round here. /board stays Lobby until Start. BoardButtons and Settings become live after a successful Load.

If another game was loaded, host already called Shutdown on it.

Examples

Keep the helper on the Game value
func (g *Game) Load(h games.Helper) error {
    g.mu.Lock()
    defer g.mu.Unlock()
    g.helper = h
    return nil
}
Gameafter Load

Settings

Returns the mux host inlines under Game Settings on /settings.

Syntax

Settings() http.Handler

Parameters

None.

Return value

An http.Handler, or nil if the game has no knobs. Nil is fine. Host then omits the Game Settings block.

Description

Host strips /settings/game. A GET of / on this mux is what gets captured into the settings page. Forms must post under /settings/game/.... After a POST, redirect to /settings so the operator stays on the host page.

This mux is live after Load and dies after Shutdown. It stays up across Stop.

Examples

Hide latency checkbox
func (g *Game) Settings() http.Handler {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /{$}", g.getSettings)
    mux.HandleFunc("POST /hide-latency", g.postHideLatency)
    return mux
}

The form action in Testing is /settings/game/hide-latency. The handler writes KV and publishes roster, then redirects to /settings.

Gamelifecycle

Start

Begins the round. After this returns nil, host hands / and /board to the game.

Syntax

Start(h Helper) error

Parameters

h
The same Helper family as Load. Store it again. Do not assume the Load pointer is the only one you will ever see.

Return value

nil to proceed. A non-nil error keeps Lobby on / and /board. Host logs a generic start failure unless the gate refused first (no seated players, or below MinPlayers).

Description

Host already checked seated count. Start the ticker, deal cards, or seed scores here. Host then marks the round active, publishes roster then round, and reloads open pages. A second Start while already started is a no-op on the host side.

Examples

Start the Testing tick
func (g *Game) Start(h games.Helper) error {
    g.mu.Lock()
    defer g.mu.Unlock()
    g.helper = h
    g.paused = false
    g.startTickerLocked()
    return nil
}

Board

Writes the TV document for GET /board after Start.

Syntax

Board(w http.ResponseWriter, r *http.Request)

Parameters

w
Response writer. Send a full HTML document, not a fragment.
r
The board request. Use HasAdmin if End game should only show for a signed-in operator tab.

Return value

None. Write the body yourself.

Description

Before Start, host never calls this. Lobby still owns the TV. After Start, this is the whole page. Stamp Theme on html[data-theme] so the first paint matches /settings. Include host chrome if you use ui-start, including the round-swap node so sse:round reloads when Stop returns the room to Lobby.

Listen for your own SSE names with HTMX. Do not open a second EventSource. Host chrome already connected one. Details are under Live SSE.

Examples

Render board.html with seated rows
func (g *Game) Board(w http.ResponseWriter, r *http.Request) {
    g.render(w, "board.html", g.boardData(r), http.StatusOK)
}

Testing lists h.Seated(), flashes a row on tap, and shows End game when h.HasAdmin(r) is true.

Phone

Writes the inner phone column for a signed-in player after Start. Seated, wait-list, and audience phones all reach this method.

Syntax

Phone(w http.ResponseWriter, r *http.Request)

Parameters

w
Host captures these bytes, then wraps Lobby gear and the claimed-host drawer around them.
r
The phone request. Read the player with PlayerFromRequest.

Return value

None.

Description

Do not send a full HTML document. No <html>. Host already sent chrome, the notch, the gear, and maybe the Host drawer. Unknown cookies never reach this method. Lobby still renders join.

A claimed-host phone gets the drawer from host, not from you. Put End game in the body if that player should end the round from the play column, as Testing does with ClaimedHost.

}

The template is a <div> with hx-post="/play/tap". Host wraps it in play-phone.html.

Play

Returns the mux mounted at /play/ for POSTs, partials, and game static files.

Syntax

Play() http.Handler

Parameters

None.

Return value

An http.Handler, or nil. Nil makes every /play request 404.

Description

Host strips /play. Register POST /tap, not /play/tap. GET is allowed after Load so info pages and CSS can load from a Lobby rail button. POST is 404 until Start, and 404 again after Stop. After Stop the Game value is still loaded, so GET handlers should tolerate a paused or stopped round.

Examples

Tap, end, partials, and CSS
func (g *Game) Play() http.Handler {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /info", g.getInfo)
    mux.HandleFunc("POST /tap", g.postTap)
    mux.HandleFunc("POST /end", g.postEnd)
    mux.HandleFunc("GET /partials/board", g.getBoardFrame)
    mux.HandleFunc("GET /static/", http.StripPrefix("/static/", http.FileServer(http.FS(files))))
    return mux
}
Gamelifecycle

Pause

Stops accepting play for a moment without ending the round.

Syntax

Pause() error

Parameters

None.

Return value

nil on success. Host then sets paused, writes a log line, and publishes pause.

Description

Operator Pause and auto-pause on seated disconnect both land here. Audience disconnects do not. A game may no-op and still return nil. Testing stops its 1s tick and ignores taps. Host may Resume while the disconnected player is still gone.

This is not Helper.Pause. Helper.Pause asks host to pause the room. Game.Pause is host telling you the room is pausing.

Examples

Stop the tick, keep tap counts
func (g *Game) Pause() error {
    g.mu.Lock()
    defer g.mu.Unlock()
    g.paused = true
    g.stopTickerLocked()
    return nil
}
Gamelifecycle

Resume

Starts accepting play again after Pause.

Syntax

Resume() error

Parameters

None.

Return value

nil on success. Host clears paused and publishes pause again so pages swap Pause/Resume chrome.

Description

If Load never ran, Testing returns nil and does not start a tick. You can no-op. Do not call Helper.Resume from here. Host already owns that transition.

Examples

Restart the Testing tick
func (g *Game) Resume() error {
    g.mu.Lock()
    defer g.mu.Unlock()
    g.paused = false
    if g.helper == nil {
        return nil
    }
    g.startTickerLocked()
    return nil
}
Gamelifecycle

Stop

Ends the round, wipes in-memory run state, and keeps the package loaded.

Syntax

Stop() error

Parameters

None.

Return value

nil on success. Host returns / and /board to Lobby, may cycle seats if the stop is graceful, resets ready, and publishes roster then round.

Description

Finish, operator Stop, and Shutdown-while-started all call this. Keep Helper. Keep KV. Drop scores, ticks, and flash marks. Start can run again without another Load. Do not delete files in DataDir unless that is your own save format and you mean to.

Examples

Clear taps, keep hide-latency KV
func (g *Game) Stop() error {
    g.mu.Lock()
    defer g.mu.Unlock()
    g.taps = make(map[string]int)
    g.flashed = make(map[string]time.Time)
    g.paused = false
    g.stopTickerLocked()
    return nil
}
Gamelifecycle

Shutdown

Unloads the package. Drop the helper and stop leftover goroutines.

Syntax

Shutdown() error

Parameters

None.

Return value

nil on success. Host clears the selected game id and Game Settings disappears.

Description

Called on unselect, on picking another game, and during process teardown of the previous game inside Load. If a round was active, host calls Stop first. KV stays until the operator hits Clear game data.

Examples

Nil the helper
func (g *Game) Shutdown() error {
    g.mu.Lock()
    defer g.mu.Unlock()
    g.stopTickerLocked()
    g.helper = nil
    g.taps = make(map[string]int)
    return nil
}

Helper

Host implements this. You receive it in Load and Start. Do not parse cookies, open host.sqlite, or write host.log yourself.

Helper

Seated

Returns every player who currently occupies a seat.

Syntax

Seated() []Player

Parameters

None.

Return value

A snapshot of Player values with Seated true. Empty if the roster read fails. Order follows Lobby's player list, not a scoreboard you control.

Description

This is the running table. Key in-memory maps by Player.ID. Disconnected seated people stay here until Kick or end-of-round cleanup. Do not use this to decide who may Join. Lobby already did that.

Examples

Paint the Testing board list
for _, p := range h.Seated() {
    row := playerRow{
        ID:          p.ID,
        DisplayName: p.DisplayName,
        AvatarSeed:  p.AvatarSeed,
        Connected:   p.Connected,
        Taps:        g.taps[p.ID],
    }
    view.Players = append(view.Players, row)
}

Waiting

Returns players on the wait list.

Syntax

Waiting() []Player

Parameters

None.

Return value

Players with Waiting true. Join during a round can put someone here and also in audience.

Description

Wait list is Lobby-owned. Fill-empty-seats consumes waiters, not audience-only people. You may show this list as "up next". You must not move people on or off it.

Helper

Audience

Returns everyone who is not seated.

Syntax

Audience() []Player

Parameters

None.

Return value

Players with Audience true. Host sets that as !Seated, so waiters are included.

Description

Use this for watch or vote UI. Audience-only people are never consumed by fill. A wait toggle drops wait and keeps audience. If you need waiters excluded, filter on !p.Waiting yourself.

Examples

Audience minus the wait line
var watchers []games.Player
for _, p := range h.Audience() {
    if !p.Waiting {
        watchers = append(watchers, p)
    }
}
Helper

Player

Looks up one roster row by Lobby player id.

Syntax

Player(id string) (Player, bool)

Parameters

id
Lobby player id. Same string you stored from Seated or PlayerFromRequest.

Return value

The row and true if it exists. Zero Player and false if not. There is no error channel. A store read failure looks like a miss (empty list).

Description

Use this when you already have an id from run state and need a fresh name or connected flag. Do not cache DisplayName across a whole night if the operator unlocked names. Re-read when you render.

Examples

Skip a tap if the id left
p, ok := h.Player(id)
if !ok || !p.Seated {
    return
}
Helper

PlayerFromRequest

Resolves the player cookie on an incoming request.

Syntax

PlayerFromRequest(r *http.Request) (Player, bool, error)

Parameters

r
The HTTP request. Helper reads the player cookie. It does not read the admin cookie.

Return value

The player, whether a row was found, and a cookie/store error. Treat err != nil as a failed lookup. ok == false with err == nil means no player cookie or no matching row.

Description

This is how play POSTs know who tapped. Host already blocked unseated phones from Phone. Play routes do not get that filter. Check player.Seated on /play POSTs yourself, as Testing does on tap.

Examples

Count a seated tap
player, ok, err := h.PlayerFromRequest(r)
if err != nil || !ok || !player.Seated {
    w.WriteHeader(http.StatusNoContent)
    return
}
g.taps[player.ID]++

Helper

KVGet

Reads an opaque byte value namespaced by this game id.

Syntax

KVGet(key string) ([]byte, bool, error)

Parameters

key
Your key. Host does not parse it. Empty key fails on write. Reads of a missing key return ok == false.

Return value

Stored bytes, whether a row existed, and a store error. Missing key is not an error.

Description

This is the game_kv table in host.sqlite. Survives Stop, Shutdown, and process restart. Operator Clear game data deletes every key for this id. Do not store Lobby identity here. That already lives on the player row.

Examples

Hide latency flag
raw, ok, err := h.KVGet("hide-latency")
hide := err == nil && ok && string(raw) == "1"

KVSet

Writes an opaque byte value namespaced by this game id.

Syntax

KVSet(key string, value []byte) error

Parameters

key
Non-empty. Empty game id or key returns an error from store.
value
Any bytes. Nil is stored as empty. Host does not parse the payload.

nil on success.

Upsert. Use it for knobs that should outlive a round. After a successful write, publish something if open pages should refresh. Testing publishes roster after Hide latency so the board drops the latency column.

Helper

Finish

Asks host to end the round as a graceful Stop.

Syntax

Finish()

Parameters

None.

Return value

None. Host swallows Stop errors.

Description

This is End game. Host calls Game.Stop with graceful true, so CycleSeats may run. Then Lobby owns / and /board again. Call this from a /play/end POST after you check HasAdmin or ClaimedHost. Then redirect. Finish does not Shutdown. The package stays loaded so the operator can Start again.

if !g.mayEnd(h, r) {
    w.WriteHeader(http.StatusNoContent)
    return
}

next := "/"
if r.FormValue("return") == "/board" {
    next = "/board"
}
http.Redirect(w, r, next, http.StatusSeeOther)

Publish

Sends a named server-sent event on the room hub.

Syntax

Publish(name string)

Parameters

name
Event name. Pages listen with HTMX sse:name. A slow page may miss an event. Every event means "fetch current state", not "here is a delta".

Return value

None.

Description

One EventSource per page, already opened by host chrome. Do not open another. The name is the only signal games get. The data line is always update. Put the new score in a GET partial. See Live SSE.

Do not publish round for a score tick. Host uses round to swap Lobby vs game documents. pause, roster, theme, and log are also host names. Publishing roster is reasonable when a knob changes a board that also shows Lobby facts.

Examples

Tick and tap

The Testing list listens with hx-trigger="sse:testing, sse:tap, sse:roster, htmx:sseOpen from:body".

Helper

HasAdmin

Reports whether this request carries a valid admin session.

Syntax

HasAdmin(r *http.Request) bool

Parameters

r
The request. Helper reads the admin cookie and checks the session table. Games never see the cookie value.

Return value

true when the session is valid.

Description

Use this for board End game, or any control that should match Room settings. Claimed-host on a phone is a different bit, Player.ClaimedHost. Testing allows End game from HasAdmin on the TV and from ClaimedHost on the phone. Settings POSTs are already gated by host with requireAdmin. You do not need HasAdmin there.

Examples

Who may end
func (g *Game) mayEnd(h games.Helper, r *http.Request) bool {
    if h.HasAdmin(r) {
        return true
    }
    player, ok, err := h.PlayerFromRequest(r)
    return err == nil && ok && player.ClaimedHost
}

Types

Player

A Lobby row as a game may read it. Games never write these fields.

Syntax

type Player struct { ID string DisplayName string AvatarSeed string Seated bool Waiting bool Audience bool ClaimedHost bool Connected bool LastHeartbeatRTT time.Duration }

Fields

ID
Stable Lobby player id. Key run state by this. Reconnect keeps the same id in the same seat.
DisplayName
Nickname. May lock while a game runs, depending on host settings.
AvatarSeed
Procedural SVG seed. Render with ui.AvatarSVG. Do not store image blobs.
Seated
Occupies a seat.
Waiting
On the wait list.
Audience
Not seated. Host sets this to !Seated.
ClaimedHost
This player claimed host. Phone End game in Testing keys off this.
Connected
Heartbeat currently live. Host maps this from !Disconnected.
LastHeartbeatRTT
Last RTT. Zero means none yet. Testing hides this when KV says so.

Examples

Format latency
if p.LastHeartbeatRTT > 0 {
    row.Latency = strconv.FormatInt(p.LastHeartbeatRTT.Milliseconds(), 10) + " ms"
}

Live SSE

Grab Bag does not push HTML down the wire. It pokes open pages with a name, and those pages pull the current document or partial. That is the whole live system.

How it works

Host chrome template ui-start puts HTMX's SSE extension on body.

<body
  class="ui-app"
  hx-ext="sse"
  sse-connect="/lobby/events"
>

GET /lobby/events is one in-process hub for the room. Every phone, the TV, and /settings share it. ui-start-quiet (setup and these docs pages) does not connect. Phone inner HTML from Phone sits inside host play-phone.html, which already used ui-start. Full board documents should use ui-start too, plus {{template "round-swap" "/board"}} so Stop reloads Lobby.

Helper.Publish sends an SSE frame like this.

event: tap
data: update

Games cannot change the data line. It is always update. Host itself uses a different helper, PublishData, only for theme (the palette id) and log (the log line). Your scores, names, and tap counts belong in the GET you run after the poke, not in the event body.

The hub writes a comment ping every 15 seconds so proxies keep the stream. Those pings are not named events. Nothing in your templates should listen for them.

Reserved names

Host and Lobby already publish these. Listening is fine. Publishing them from a game is almost always wrong, except roster after a knob that other pages should reread.

NameWho publishesWhat pages do
rosterjoin, leave, ready, seats, disconnect, Load, and similarSwap roster partials
roundhost on Start, Stop, ShutdownReload / or /board (Lobby vs game swap)
pausehost on Pause and ResumeSwap pause chrome and paused game frames
themehost when the palette flipsSet html[data-theme]
loghost log ringRefresh the settings log tail

If you publish round because a prompt advanced, every open TV and phone reloads as if the round ended. Use your own name.

Your own names

Pick a short lowercase token. Prefix with the game id when the word is generic. Testing uses testing for a 1s room tick and tap when someone hits the plunger. Only one game is loaded at a time, so tap will not collide with another package. It can still collide with a reserved host name. Do not call your event round.

Publish after the run state you care about is already stored. Listeners will GET immediately. If you publish first and then write the map, a fast TV can fetch the old count.

Examples

Publish after a tap is counted
g.taps[player.ID]++
g.mu.Unlock()
h.Publish("tap")
Publish a clock tick
if h != nil {
    h.Publish("testing")
}

A settings POST that only changes KV can publish roster if the board list already listens for it. Testing does that for Hide latency. You can also publish your own name and list it on the same hx-trigger.

Listen in HTML

HTMX turns a named event into sse:that-name on the same EventSource. Point hx-get at a Play partial. Swap the node that holds the live bits, not the whole document, unless you really want a reload.

Examples

Refresh a list on tick, tap, roster, and reconnect
<div
  id="testing-list"
  class="testing-list"
  hx-get="/play/partials/board-list"
  hx-trigger="sse:testing, sse:tap, sse:roster, htmx:sseOpen from:body"
  hx-swap="outerHTML"
>

htmx:sseOpen from:body runs when the EventSource connects, including after a drop. Use it so a phone that slept still catches up. The first HTML response already has the list, so the extra GET on first open is cheap insurance, not the first paint.

Swap the outer frame only on pause
<div
  id="testing-board"
  hx-get="/play/partials/board"
  hx-trigger="sse:pause"
  hx-swap="outerHTML"
>

Testing keeps pause on the outer frame and ticks on the inner list so a 1s tick does not rebuild End game and the heading.

Register those GET paths on your Play mux (GET /partials/board-list, not /play/partials/board-list). Do not add another sse-connect. Do not construct new EventSource("/lobby/events") in a script. A second connection still shares the hub, but the lost-host overlay and theme-sync are wired to the body one.

Missed events

Each page gets a buffer of 16 named events. If the tab is slow, the hub skips that subscriber and moves on. There is no replay. The next event, or htmx:sseOpen, should GET a partial that represents now, not "plus one since last time".

That is why Testing stores tap counts on the server and re-renders the list. A missed tap only delays the flash. The next testing tick still shows the true total.

If you animate from the event itself and ignore the GET, a dropped poke is a dropped animation with no recovery. Prefer server state plus refetch.

Must not

  • Import internal/host, internal/lobby, or internal/store from a game package.
  • Write seats, name, wait, audience, or claimed-host.
  • Parse the player cookie or the admin cookie.
  • Register /, /board, or /settings as mux roots.
  • Clear KV on Stop or Shutdown.
  • Scan a games folder at runtime.
  • Treat /docs as this contract. That URL is how to run the binary.
  • Open a second EventSource on a page host already wired.

The live package that exercises almost every hook is Testing in internal/games/testing.
